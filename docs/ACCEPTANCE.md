# Acceptance: prove the player, not just the build

Record actual pass/fail/unrun results against a source and build identity.
Source builds and selected desktop boot/storage markers pass. On the stock Fold,
installation, retained read-only media validation, native kernel boot and Fable
executable loading have been observed. The run then quick-reboots to a missing
dashboard and fatal error 21. Gameplay, audible sound, touch acceptance, ordinary
saves/reload, full resume, shortcuts and gameplay performance remain unqualified.
See BUILD.md and live XBX-1 for the exact evidence. Compatibility lists do not
replace integration observations.

## Source and build

Reproduce the selected engine, required assets and Rust host from exact inputs.
Verify symbols/ABI and native dependencies before installation, supported CPU
execution/renderer path, notices, signature and correct distinct app ID. Build
without unpinned downloads or private inputs entering public artifacts. Separate
ELF/ZIP alignment from actual 16 KB runtime qualification.

## Gameplay

From ordinary local import, reach moving gameplay in one owner-selected original-
Xbox title with simultaneous analog/digital/touch input, clear audible sound and
a usable no-stretch picture. Check external controller connection/disconnection
when that capability is implemented. Boot/menu/render counters are lesser results.

Measure actual emulation speed versus intended guest rate, presentation/frame-time
distribution, audio underruns, native/GPU/JIT memory and available thermal signals.
Use a repeatable gameplay interval plus a longer warm-device observation when
feasible. Separate startup and transition costs. No universal compatibility or
thermal endurance claim from a brief run. Do not conceal slowdown with guest
underclocking, skipped work or a misleading FPS counter.

## Durable progress and resume

XBX-CARTRIDGE-1 requires an original unsaved RAM state to survive two genuinely
fresh runtimes through the same shared session policy, then A -> B -> A with
isolated storage. A terminal fixture is mechanism evidence, not controller or
Fable acceptance. Record actual native quiesce/capture/load/retire acknowledgments,
latency, allocated/apparent bytes and observed memory. Saving while already paused
with no presentation surface must not depend on a later displayed frame. Exercise
newer ordinary saves, interrupted publication, incompatible/damaged state and
partial native load against synthetic profiles before claiming safe automatic return.

Complete an ordinary in-game HDD save; fully restart the app and load it through
the game's own menu. Independently prove complete checkpoint resume to a known
scene. Test game A -> game B -> game A after both acquired meaningful progress.
Check the disk, EEPROM and machine-state generation bindings.

Create a newer save after an old checkpoint in isolated test storage. An attempt
to load the old state must not silently discard that save. Missing base/overlay,
wrong firmware/core, corrupt state, killed writer, unavailable content and full
storage use fixtures; never deliberately exhaust the owner's device or modify
their only live save. Preserve errors and show an actionable recovery route.

Include process death after the dirty-runtime epoch is durable but before a
checkpoint commit, and verify final lineage validation happens under the OS
lease. Test checkpoint requests while the surface is hidden and the VM already
paused: no dependency on a later visible frame, no stale device-state capture,
and no delayed native publication after ownership changes. A pause request is
not quiescence; a completed block fixture is not an in-game save or VM resume.

Check supported app update with retained IDs, disk lineage and signing identity.
No claim of arbitrary cross-core state compatibility. A normal reboot/restart is
safe only where authorized and does not interrupt unrelated user work.

## Lifecycle and launch

Pause/resume, audio focus loss, Home/return, process death and surface transitions
retain correct pause intent, media and storage. Folds/rotations cancel input and
adapt the viewport without resetting the guest. Repeated cold/warm shortcut
requests create no duplicate owners. Launch another game only after safe current
state handling; invalid/missing targets do not destroy it.

Confirm Android pinned-shortcut creation through the launcher's completion path,
then tap the real icon. Verify local recovery after content relinking. Removing
an icon leaves game and progress intact. iOS URL/Shortcut semantics are a design
contract until there is an actual qualified iOS build.

## Handoff

Provide commit/build hashes, exact reproduction, source/license inventory,
ordinary save versus full-resume results, original/current disk preservation,
performance observations, unresolved limits and the verified device return.
Master accepts the result separately from compilation or issue publication.
